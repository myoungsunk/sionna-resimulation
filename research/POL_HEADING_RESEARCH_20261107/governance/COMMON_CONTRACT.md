# 연구 제안·구현·감사 공통 계약

정책 ID: RESEARCH-GOVERNANCE-v1 (2026-10-29).

## 적용 범위와 시작

연구 질문에 답하기 위한 실험 제안, 과학 계산 구현, 검증·감사, 결과 해석에 적용한다. 단순 편집이나 일반 질의를 새 연구 캠페인으로 만들지 않는다. 사용자 범위·중단 조건·기존 동결 계약을 존중한다. 이 문서는 실행, 하드웨어 동작, 하위 에이전트 생성에 대한 추가 권한이 아니다.

작업 시작 시 역할(PROPOSER / IMPLEMENTER / AUDITOR), 대상 저장소·브랜치·실제 커밋, 질문 ID, 적용 지침의 커밋 또는 파일 해시를 기록한다. 같은 실험의 역할들은 동일한 지침 버전을 사용한다. 연구 브랜치에 이 문서가 없으면 명시된 정책 커밋의 문서를 읽고 출처를 기록한다. 지침 변경은 기존 실험에 소급 적용하지 않는다.

[제안](ROLE_PROPOSER.md), [구현](ROLE_IMPLEMENTER.md), [감사](ROLE_AUDITOR.md) 중 해당 역할만 추가로 읽는다. 한 사람이 여러 역할을 순차 수행하면 이를 표시하고 자기 검사를 독립 감사라고 부르지 않는다.

## 검증 연결

질문 ID → 수학·실험 계약 → 함수·코드 위치 → 입력·실행·출력 → 검사 → 허용 주장으로 연결한다. [실험 계약](templates/experiment-contract.md), [감사 기록](templates/audit-report.md), [주장 목록](CLAIM_REGISTER.md)을 사용하되 기존 동등 문서에 필요한 항목이 있으면 중복 생성하지 않는다.

- 파일 해시 일치, 결과 재집계 일치, 구현 정확성, 실험 타당성, 일반화는 별도 판정이다.
- 실행 성공, 감사 완료, 결함 수정, 재검증, 채택을 분리한다. 감사가 끝나도 결함은 열려 있을 수 있다.
- 반사실·참값·LoS 참조를 쓰는 오프라인 진단을 온라인 알고리즘으로 주장하지 않는다.
- seed·순열 반복과 독립 RF·환경 반복을 구분한다. 사후 선택 조건으로 모집단 실패 확률을 추정하지 않는다.
- 분산과 중심화하지 않은 2차 모멘트, NEES 감소와 일관성 개선을 구분한다. 표본 범위·자유도·목표·의존성을 명시한다.
- MB_VAR에서는 Δs 기반 거리 평균 보정과 편파 분산 추가를 분리한다. 분산 조회 시점, gate, donor, Q/R 및 상태 의존성을 명시한다.

## 단계와 변경

1. 제안 → 구현: 질문, 경쟁 설명, 수학, 개입·통제, 지표·제외·판정 규칙, 주장 한계가 정해져야 한다.
2. 구현 → 본 실행: 기준선 일치와 결과에 중요한 수학·동작 검사가 통과해야 한다. 실패하면 영향받는 실행을 중단한다.
3. 실행 → 감사: 실제 실행 인자·환경·커밋·시각·종료 상태·입출력 해시와 누락·실패·예외를 제출한다.
4. 감사 → 결론: 미해결 결함과 영향받는 주장을 연결한다. 수용은 명시된 범위에만 적용한다.
5. 수정 → 종료: 영향받는 검사·결과를 갱신하고 이전 주장에 정정 링크를 붙인다. 원본 증거를 덮어쓰지 않는다.

결과를 본 후 변경한 기준은 사후 분석으로 따로 기록한다. 동결 기준을 소급 완화하지 않는다. 계약 오류는 제안으로 반환하고, 구현 오류는 구현으로 반환한다. 자동 사용자 승인 절차를 추가하지 않으며, 기존 권한 안의 일상적 선택은 진행한다. 해석을 바꾸는 미확정 선택이나 범위 확대만 명시적으로 해결한다.

## 자동 검사와 판단

조건 완전성·중복·해시·기록·수치 허용오차는 기계적으로 검사할 수 있다. 수학적 타당성·인과 식별·주장 범위는 별도 판단이 필요하다. 이 문서 자체가 CI 또는 독립 감사를 설치하거나 수행한 증거는 아니다.
