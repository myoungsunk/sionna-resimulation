# G7 필터 재생 불일치(309/4,200) 원인 분류 — L1 / L2 / L3

날짜 2026-10-12. 입력: `out_div/replay_{A,B,C,D}.csv`(7개 기존 조건 × drift 3 × seed 50 × arm A–D = 4,200회씩), 게시값 `RUN_01a124ff/OUTPUT/09_V2_main.csv`. 시점별 상태·상태판정 trace(`div_{A..D}/*.npz`, 각 약 1.1 GB)는 용량 때문에 커밋하지 않았고 파일별 SHA256을 `out_div/trace_sha256_manifest.csv`에 보존했다. 같은 trace는 `scripts/simulate_div.py`로 재생성된다(환경 의존, 아래 L2).

| 재생 | 설정 |
|---|---|
| A | 이 기계, 기본 BLAS 커널 |
| B | 같은 기계·같은 코드, `OPENBLAS_CORETYPE=HASWELL` |
| C | A와 같은 설정 + 관측 `s`, `range_m`에 무작위 ±1 ulp 교란(0 포함) |
| D | A를 한 번 더 |

(C의 첫 실행은 교란 코드가 `0·inf=NaN`을 만들어 일부 관측을 결측으로 만든 **내 구현 오류**였고 폐기했다. 위 수정판으로 다시 돌렸다.)

## L1 — 입력·관측 재현성
- 동결 `audit.work()`의 관측기 parity assert 전부 통과(12조건, 최대 |Δs|=|Δpower|=|Δrange|=0).
- 게시된 `01_FEATURES.csv`/`02_LABELS`와의 회귀는 최악 상대오차 2.8e-16 / 2.4e-15로 **통과(≤1e-12)지만 비트 동일은 아니다**. 즉 L1은 "1 ulp 수준에서 같다"이며, 이 정도 차이가 L2 불일치의 입력 후보다. 게시 당시 OBS 파일이 저장소에 없어 직접 비트 비교는 불가(NOT_RUN).

## L2 — 수치 재현성 (엄격 비교: 3개 지표 중 하나라도 1e-9 초과)
| 비교 | 불일치 / 4,200 | arm A / B / C / D |
|---|---:|---|
| A vs D (같은 환경 반복) | **0** | 0 / 0 / 0 / 0 |
| A vs 게시값 (다른 CPU·Python) | 309 | 0 / 76 / 19 / 214 |
| A vs B (BLAS 커널만 변경) | 296 | 0 / 73 / 14 / 209 |
| B vs 게시값 | 242 | 0 / 11 / 16 / 215 |
| A vs C (±1 ulp 입력 교란) | 304 | 0 / 65 / 21 / 218 |
- **같은 환경에서는 비트 재현 PASS**: A와 D의 4,200개 trace 파일이 바이트 단위로 같다(SHA256 4,200/4,200 일치).
- **환경이 바뀌면 비트 재현 FAIL**: 커널 교체 296, 게시값 309, ±1 ulp 입력 교란 304로 세 가지 미세 교란이 거의 같은 수의 run을 바꾼다. 따라서 309건은 특정 구현 차이가 아니라 **마지막 비트 수준 교란에 대한 필터 재생의 민감도**로 설명된다(원인을 하나로 특정한 것은 아니다. 게시 당시 CPU/라이브러리 직접 재현은 못 했다).

## 불일치의 위치와 형태 (`out_div/g7_div_location.json`)
상태가 1e-10 넘게 달라진 run: A–B 218건, A–C 225건.
- **gate 반전(accept/reject)은 0건.** odom/range/s 어느 갱신도 판정이 바뀐 run이 없다(218/218, 225/225 "상태판정 불변"). 이전에 세웠던 "gating 경계 반전이 원인"이라는 가설은 **기각**한다. 차이는 상태가 연속적으로 증폭되는 형태다.
- arm D(`s` 사용)가 214/218, 220/225. `s`를 쓰지 않는 arm A는 0건.
- 조건은 R2_aA_m0(151/149), R5_aA_m0(38/45), R5_aB_m0(29/31)에만 있다. 앵커 축 가까이 지나는 조건이다.
- 첫 분기 시점의 앵커까지 수평거리 중앙값 **0.52 m**(사분위 0.52–0.55, 최소 0.06–0.10 m). 루트 전체 중 앵커 1.5 m 이내는 약 15–16%다. 즉 로봇이 앵커 천정점(극점) 근처를 지날 때 `s` 모델의 민감도가 커져 1e-16 교란이 증폭된다. 이는 pole 근방의 수치 민감도에 대한 정황 증거이며, LUT/야코비안 자체의 결함이라는 증거는 아니다.

## L3 — 통계적 동등성
**동등성 한계(이 분석 실행 전에 고정, 단 평균 차이가 매우 작다는 점은 이미 본 상태):** log 헤딩 RMSE·log 위치 RMSE의 paired 평균 차이 ±1 %, log 평균 NEES ±2 %, pose 포함률 ±1 %p(모두 TOST α=0.05), 그리고 run별 상대차 p99 ≤ 5 %. 최댓값은 보고만 한다.
- 비교 5쌍(A–게시값, B–게시값, C–게시값, A–B, A–C) × RF 사용 arm 3종(B, C, D) = 15칸 모두에서 세 지표와 포함률의 TOST **동등**, p99 한계 충족(B–게시값, C–게시값 쌍은 요약 JSON에 있음).
- 평균 로그 차이 크기: arm D 기준 헤딩 ≤ 1.6e-7, 위치 ≤ 3e-6, NEES ≤ 7e-7(A–B); ±1 ulp 교란(A–C) 위치 −1.1e-6, NEES 4.8e-6.
- run별 상대차 p99: arm D에서 ≤ 1e-4. **최댓값(꼬리)**: A–B에서 위치 RMSE 0.41 %, NEES 0.12 %; ±1 ulp 교란(A–C)에서 arm C의 위치 RMSE 2.8 %, 헤딩 0.6 %. 극단적인 NEES·포함률 문제가 사라졌다는 뜻은 아니고, 이 7개 조건·150 seed 규모에서 평균과 꼬리 모두 위 한계 안이라는 것이다.
- 한계: 이 7개 조건은 한 복도에서 나온 상관된 시뮬레이션이다. 동등성은 이 계산 가족에 한정된다.
