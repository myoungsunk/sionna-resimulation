## 2. 결함 진단 (G3_v1 R2_aA, 위치 x3.7036_y-0.5204)
G3_v1은 지연(τ)만 쓰는 최근접 매칭 + 고정 창 5e-14 s였다. 실제 잔차 5.11e-14 s는 float32 간격(τ≈1e-7 s에서 7.1e-15 s)의 **7.2배**로, 3-반사 경로의 반올림 누적 범위 안이다. 창이 고정값이라 경계에서 같은 경로가 “missing 1 + spurious 1”로 쪼개졌다(경로 식별 오류가 아니라 수치 매칭 결함). 단순히 창만 넓히면 서로 다른 유효 지연의 최소 간격(1.03e-13 s)과 겹치므로, 지연창을 넓히는 것으로는 해결하지 않는다.

## 3. G3_v2 방법 (`g3_v2.py`)
- 기하 유효 시퀀스마다 지연 τ, **출발 방향**(TX→첫 반사점), **도착 방향**(RX→마지막 반사점) 계산. 각도 규약은 R2_aA LoS에서 검증(출발=전파방향, 도착=−전파방향; 오차 ≤5e-7 rad). trace `ang` 행 순서 = [θ_t, φ_t, θ_r, φ_r].
- 시퀀스–trace 경로가 **feasible** ⇔ |Δτ| ≤ K·spacing_float32(τ) **그리고** 출발·도착 각 차이 ≤ A.
- feasible 쌍 위에서 **1:1 Hungarian 배정**(`scipy.optimize.linear_sum_assignment`, 비용 = 정규화 제곱합). 미배정 시퀀스 = missing, 미배정 trace 경로 = spurious.
- 기준 1–3(LoS·1차 100 %, 2·3차 ≥ 99.5 %, 위치당 missing ≤ 6)은 **변경 없음**. 기준 4는 내용 동일(spurious 0).
- 1차 허용값: **K = 16, A = 1e-2 rad**.
  - K: 관측된 지연 잔차 최대 7.2 ulp(5.11e-14 s) 대비 2배 여유. (사후 설정)
  - A: delay-unambiguous 경로의 각 잔차(출발 ≤ 6.6e-4 rad, 도착 ≤ 1.7e-5 rad; `ang_residuals.txt`)보다 15배 크고, 지연이 가까운 서로 다른 시퀀스 간 최소 각 간격(9.8e-2 rad)보다 약 10배 작음. (사후 설정)
  - 따라서 두 값 모두 G3_v1 결과를 본 뒤 정해졌다. 이를 보완하려고 K∈{4,8,16,32,64} × A∈{1e-4…1e-1} 전 격자를 `g3_v2_sweep.json`에 기록.

### 식별/모호성 감사 (K=16, A=1e-2)
- 완전 모호(서로 다른 후보 ≥2가 지연·각 모두 창 안): **0건**.
- 지연만 보면 모호한 경로: 위치 있는 세트 2–20곳(경로 8–90개). 그중 **지연 최근접이 배정과 다른 경우**가 R4·R2에서 각 3건, R5에서 26–28건 → 지연-only 매칭은 이 경우 식별을 틀릴 수 있었고, 각도 정보가 이를 막는다.
- 매칭된 쌍의 최대 |Δτ| = 5.11e-14 s, 최대 각 잔차 6.6e-4 rad(모두 출발각).
- 관찰: 반사 경로의 출발각 잔차 p99가 앵커 B에서 6.4e-4, 앵커 A에서 2.9e-4 rad로 중앙값(~4e-6)보다 두 자릿수 크다. 도착각에는 없음. 게이트에는 영향 없으나 원인은 미조사(별도 항목).

### 민감도 (`g3_v2_sweep.json`)
- K ≥ 8 이고 A ∈ [1e-3, 1e-1]인 전 구간(약 20개 조합)에서 결과가 **완전히 동일**(missing 280, spurious 0, 기준 전부 통과) → 경계 의존적이지 않음.
- 실패 영역(공개): K = 4(최대 지연 잔차 7.2 ulp보다 작음) → spurious 4~112; A = 1e-4(출발각 잔차 6.6e-4보다 작음) → 대부분 불일치. 두 경우 모두 허용값이 관측 수치 잔차보다 작아서 생기는 실패.

## 5. 해석 제한
- 허용값은 사후 보정이다. 독립 검증이 아니라 G3_v1 결함 수정의 일관성 확인이다.
- 기준 2·3(99.5 %, ≤6)은 R4_aB에서 보정된 값이며 나머지 5세트는 held-out 확인이다(변경 없음).
- G3_v2는 레거시 trace의 기하 경로 완전성만 검증한다. Native 동등성은 원래 V01b FAIL로 유지.
