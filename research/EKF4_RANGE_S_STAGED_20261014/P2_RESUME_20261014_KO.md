# P2 재개 및 능동 문제 해결 계약

사용자 요청: P2부터 다시 실행. 단계별 검증 후 진행하고, 예상 밖 결과는 가정과 비교하여 진단한다. 논리적 가설을 기록한 문제 해결 trial을 능동 실행하되, 그 trial 이후 다시 미해결 상황이면 중단하고 확정/미확정을 보고한다.

기준: 9485133c233ec809ea11d92bf4be64d41e53e9f0, R1 core.py SHA256 b8cd844003a865fc02b41286233980278b4ea7a2140b1fabe440166d8894afa9.

## 첫 재개 실행
- 같은 커밋에서 P0/P1 및 R1 동결 실패 회귀검사를 통과해야 P2로 진입한다.
- P2_SPEC.json SHA256 548258a444c02a3a1d0c2d210b470489560b1bd56ad911cc9ee93d7631b36ce7 유지.
- synthetic.py SHA256 c3fc54d9726beab176971aa8652c0b6f61353f55f596613e4c8150351c4d9643 유지.
- 직진/회전/후진왕복 × bias 0/+0.05 deg/s × 100 trial × EKF3/EKF4/MAP3/MAP4, 기존 모든 seed와 분석창, Q/R, gradient 1e-8, 반복 한도 80 유지.
- 기존 실패 trial을 건너뛰지 않고 처음부터 전체를 재실행한다.
- 계산은 GitHub-hosted Actions에서만 수행한다. 로컬은 내려받은 산출물의 해시/집계 감사와 코드 작성만 허용한다.

## 문제 대응
- P2가 수치 오류로 중단되면 원시 FAILED_STEP/FAILURE/부분 trace를 보존하고 미수렴 입력에서 목적함수·gradient·곡률·종료 규칙을 조사한다. 알고리즘 정확도 가설 실패와 혼동하지 않는다.
- 진단 후 한 문제 해결 trial의 변경 및 가설을 별도 기록하고 push한다. 모델 수정이면 필요한 새 가정과 기존 대조군을 분리한다. 수치 수정이면 목적함수와 수렴 허용치를 바꾸지 않는다.
- 회귀검증→동일 P2 재실행으로 해결 여부를 확인한다. 이 해결 trial에서도 다시 미해결 오류/가설 모순을 만나면 P3 이후로 넘어가지 않고 STOP한다.
- 모든 세 경로의 사전등록 효과가 지지되고 수치 검증이 통과하면 기존 P3→P6 계약에 따라 다음 검증을 구현·실행한다. 아직 없는 구현이나 미실행 결과를 완료로 표현하지 않는다.
- P2에서 과학 가설이 미지지일 때는 gate를 완화하지 않고 조건별 오류 및 bias 회복을 분해한다. 사후 개발 결과를 독립 확증으로 올리지 않는다.

## 보존
과거 PLAN/P2_SPEC/R1 보고서와 실패 스냅샷은 수정하지 않는다. 새 결과는 run ID별로 저장하며 성공·실패 모두 artifact를 업로드한다. pipeline 실패 exit code를 유지한다. scientific_PASS=false를 기본 유지하고 합성·한 장면·수학 검사의 범위를 분리한다.
