## 2. Methodological findings

**F1 — Original preregistered technical gates genuinely FAIL.**
A007 C2-a requires output e/P reproduction ≤1e-3 on all 1080 and C2-d requires ≤1% NONCONVERGED for **each** (arm,window,cell). Neither is satisfied. A007 correctly stopped HOLDOUT2; no retroactive A007 PASS. Green Actions must not replace MANIFEST status; here GitHub C2 run is correctly FAIL.

**F2 — Kink is strongly associated with instability, but not proven as the unique mechanism.**
Every C2-a mismatch and all four C2-d nonconverged estimates have at least one FD-vs-analytic Jacobian kink. However \`kink_count\` and \`CONVERGED_NONSMOOTH\` depend on closely related Jacobian diagnostics, so the 92% versus 0% association partly reflects shared definitions. It is evidence for numeric Jacobian sensitivity, not independent proof of correct uncertainty or global optimality.

**F3 — “input equality” is not actually verified by C2-a.**
\`code/c2_conv.py::cmd_aggregate\` compares only \`e_*\` and \`P_*\` after reconstructing the random field; it does NOT check binary/quantized hashes of \`z\`, \`ds_m\`, \`gy_m\`, selected taps, control noise, or initial prior against the S1V2 DEV run. Reproducible estimates strongly suggest identical samples, but the upstream-input claim remains incomplete. V3 must log separate INPUT_REGEN and ESTIMATOR_OUTPUT_REPRO statuses.

**F4 — Cost gap is only relative to the 10 enumerated starts.**
C* is best among start-0, seven heading starts (one duplicate with E), +x, +y, and truth diagnostic. Thus \`cost(E)-C*<1\` rejects gross failures versus those candidates; it is not proof of the true global optimum or of correct posterior variance. The cost gap of 0.16 can coexist with a 0.64 posterior-SD state difference.

**F5 — Current \`P\` is a Gauss–Newton/Laplace curvature approximation at a kink.**
\`filters.batch_map_v2\` computes \`Ctheta=(A^T A)^−1\`, \`P_k=J_k Ctheta J_k^T\`. At a discontinuity of the Jacobian, this is not a mathematically unique approximation. A central-FD Jacobian chooses one regularization scale and is **not an exact posterior covariance**. Changing only P and a P-normalized remaining-GN-step can stabilize reporting, but is not a statistical proof. The C2-c state difference is itself normalized by the potentially unstable \`PendE\` covariance.

**F6 — Original per-cell 1% criterion has hard zero-count behavior for n=30.**
One failure = 3.33% and immediate FAIL. Zero out of 30 does not establish a <1% underlying population failure rate; report this as a technical gate, not a statistically validated rate. Changing it after this C2 requires transparent A008 + fresh independent DEV, preserving the original C2 FAIL and original-rule result in parallel.

**F7 — Some less-material aggregation wording must be corrected.**
\`C2g_xmodel_REPORTED.truth_start_worse_than_E_frac\` is calculated across *all* C2 rows, not XMODEL only. Rename or filter. Primary run statistics unaffected.

## 3. Recommendation: Option 1 conditional; Option 2 not primary

Choose **Option 1** only as a separate **post-fit derivative/covariance stability analysis**, with the actual measurement model and optimizer objective left unchanged. Do **not** simply overwrite all covariance results with central-FD P and call old failures resolved.

### Required A008 content to freeze BEFORE fresh DEV2 10–19

1. **Evidence:** lock previous A007+C2 FAIL; record that A008 was formulated after C2 evidence and is exploratory/engineering until evaluated on untouched DEV2 (10…19). Preserve HOLDOUT2 5000…5059 and reserve 5060…5119 entirely unopened.
2. **Separated recomputability:** save SHA256/float64 raw array fingerprint (or independent tolerance-bounded representations) of \`z\`, \`x0/P0\`, \`ds_m\`, \`gy_m\`, \`tap\`, sample pose keys, source/covariance model for every (field,role,cell,sensor,arm). Original comparison \`C2a\` is to be split into INPUT_REPRO, STATE_COST_REPRO, P_REPRO and STATUS_REPRO. When historical original lacks input arrays, do not claim retrospective bit parity; both new DEV2 and new C2 need matching input receipts.
3. **Preserve MAP estimates:** run \`batch_map_v2_ms\` unchanged for the reference; evaluate central-FD, left/right and multiple perturbation scales at **the same fixed estimate**, without changing chosen basin, state, or objective. Store \`P_analytic\`, \`P_central\`, \`P_left\`, \`P_right\`, and directional/scale sensitivity, PSD checks, normalized curvature/condition metrics. If P remains unstable, flag \`KINK_P_UNCERTAIN\` rather than fabricate a stable result.
4. **Separate convergence from arbitrary P:** use cost-relative-to-start-grid, actual accepted-step descent, finite directional objective perturbation, and stability of the final state using an externally fixed reference scale (for example prior/frozen S0 scale). Do not use only the convention-dependent \`GN_shift/sqrt(P_analytic)\` to decide convergence; still report old A007 categories for transparent comparison. Wrong-covariance XMODEL can have legitimately large chi² and is not by itself a wrong basin.
5. **Statistical interpretation:** empirically check coverage and standardized-error/NEES on fresh synthetic fields, stratified by kink/nonkink and by arm/window/cell, with field-level uncertainty. A stable central-FD P is a candidate numerical convention, not a validated posterior; material calibration failure -> scientific gate FAIL, irrespective of numerical reproducibility.
6. **Sensitivity/control:** random/adversarial kink fixtures, 0/1/2-sided derivatives at ±multiple registered steps, near-linear exact Gaussian parity, and an explicit smooth-pose negative control; compare whether derived S1 H1/H2/H3/CAL/H4 verdicts change under the covariance convention. Freeze tolerances linked to scientific effect margin, not selected ex post to force a pass.
7. **Validator:** preserve A007 old PASS/FAIL; new A008 acceptance defined before any DEV2 result. Convergence-rate goals must be explicit by arm/cell with failure rows retained; do not silently replace original 1% gate with pooled metric.
8. **CI:** if MANIFEST.execution_status=FAIL, aggregate still uploads evidence but GitHub Actions must end FAIL. Do not run or uncover HOLDOUT2 or RT while new DEV2 QA/auditor review is incomplete.

**Option 2** (replace bilinear FFD interpolation with smooth interpolation in both generator and estimator) changes the scientific data-generating mechanism. It belongs to a separate sensitivity experiment, with a new FFD/RT parity assessment and design contract. It is not the first choice for this controlled Track S mechanism test and cannot be presented as equivalent to the original physical RF chain.
