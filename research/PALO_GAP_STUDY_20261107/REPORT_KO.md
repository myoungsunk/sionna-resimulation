# PALO-GAP-002 실험 결과

질문: 완벽한 즉시 Heading 손익 오라클과 온라인 정보만 쓰는 신뢰도 판정기 사이의 간격. 기존 입력·운영 코드 변경 없음. 이 결과는 R2/anchor B/seed0 개발용 진단이며 독립 일반화 검증이 아니다.

총 636개 저장 궤적(각 979시점): 기준 12, RF 정책 32, 횟수 일치 무작위 대조 80, 오류 주입 480, 시간 분할 개발 대조 32. 추가로 24개 zero-error limit 및 truth perturbation을 검사했다. 오류 반복 seed는 독립 RF 표본이 아니다.

## 2. 온라인 특징과 손익
FEATURE_ASSOCIATIONS.json, FEATURE_QUARTILES.json, FEATURE_COUNTEREXAMPLES.json에 S4/DR/Heading 각 prior의 전체 관측을 기록했다. AUC는 큰 특징값이 유익함을 뜻하는 방향으로 계산했다. 0.5 미만이면 반대 방향 관련성이다. 시점·수준·prior의 의존성 때문에 p-value나 일반화 정확도를 주장하지 않는다. Hpsi는 민감도이며 정보량과 동일하지 않다.

## 4. 공분산
거부 시 predicted P를 그대로 유지하고 수용 시 원래 갱신식을 사용하는지 확인했다. COVARIANCE_SUMMARY.csv와 REACCEPTANCE_EVENTS.csv에 5프레임 이상 거부 후 재수용 사건의 오차·P·NEES를 기록했다. 95% 임계 초과는 해당 사건의 기술적 지표이며 보정 여부의 통계적 검정이 아니다. 공분산 감소와 오차 증가를 분리해서 집계했다.

## 5. 개발용 온라인 판정기

## 검증·재현
CONTRACT.md 사전 기준, results/EXECUTION_PROVENANCE.json 코드/입력 해시, results/CHECKS.json 기준 재현·수식/진리표/참값 교란 검사, analysis/VERIFY_RECEIPT.json 저장 궤적 재집계 검사. 원본 입력 86개 해시 재검사. 모든 결과는 자체검증이며 이번 추가 실험의 독립 감사는 미실행.
실행: python -B campaign.py; 완료 후 python -B analyze.py. 결과 폴더가 이미 있으면 덮어쓰기를 거부한다. engine.py의 PRIOR는 보존된 이전 패키지 경로를 참조한다. 원본 입력을 복제하거나 수정하지 않았다.
