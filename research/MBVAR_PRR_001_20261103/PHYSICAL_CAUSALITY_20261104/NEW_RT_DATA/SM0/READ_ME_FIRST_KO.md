# SM0 실행 결과 — R4-B pose 194에서 중단

15개 중 첫 대조의 257개 주파수 계산을 완료했다. **원본 LoS 복소 채널 대조 실패**로 승인된 pose는 0개다. 추가 14곳은 실행하지 않았다. C0-B 반사경로별 원인 판정과 이번 순서에 따른 C1 진입은 보류한다. [15개 pose의 실행 상태](delivery/INDEX.csv) · [원시 데이터 및 실행 기록 ZIP](delivery/SM0_R4B_194_STOP_RAW.zip)

## 첫 대조

R4-B pose 194, 38.8초, (6.103209, −0.269105) m, yaw −39.343083°. 원본 경로·물체·재질·양 편파 FFD bank, 송수신기 배치, solver seed 20260924를 사용했다. 고정한 Linux 환경에서 Sionna RT 2.0.1, Mitsuba 3.8.0, DrJit 1.3.1의 편파 LLVM solver를 실행했다. 실행 코드는 b8a8dc5ed68fb808e1a95d705d4bba72fbf0c2bc, 독립감사의 실행 허가는 한 곳으로 한정했다. ## 원시 계수로 검산한 실패 원인

같은 데이터에서 과거 계산식의 직접파를 대조하면 원본 LoS와 상대 L2 차이가 1.526e−7이다. 동결한 float64 직접파의 **진폭** 차이만 비교해도 약 1.443e−7이다. 복소수로 비교할 때에는 주파수별 작은 위상차가 남는다. 현재 결과는 보관한 계수와 지연을 복소장으로 변환하는 위상 연산의 정밀도 차이를 가리킨다. 저장된 계수에 대해 연산을 다시 대조한 진단이며, 이전 방식의 작은 오차를 근거로 이번 float64 기준을 교체하지 않았다.

첫 대조를 통과하지 않아 경로 제거·반사면별 전력 기여 분석을 수행하지 않았다. 이 실행으로 R4 33–35초, R5 196초 부근, R2 525번의 원인 경로 또는 EKF Heading 과신의 인과관계는 판정할 수 없다.

## 전달 파일과 재현 순서

ZIP 안의 RAW.npz는 전체 ragged 경로 배열이고 bins/는 257개 주파수별 원래 출력이다. scene/은 실제 solver에 적용한 PLY를 담는다. ARTIFACT_HASHES.json과 delivery/MANIFEST.json에서 개별 파일과 ZIP의 SHA256을 확인할 수 있다. 원본 임계값을 사용한 구현, 실제 실행 명령, 실행 로그, 중단 이후 계수 연산 대조를 함께 보관했다. 같은 환경에서의 실행 절차는 원본 24개 입력과 bank의 해시 확인 → runtime lock 확인 → 사전 허가와 코드 해시 확인 → 단일 pose 실행 순이다. 이번 실패 상태에서 다른 pose를 이어 실행하는 절차는 승인되지 않았다.
