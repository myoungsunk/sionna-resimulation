범위: 후보 생성 수정 설계와 E1 재검증 계획만. 구현·실행·E2·선택기 학습·EKF 실행 없음.

## 질문과 경쟁 설명

질문: 현재 CIR만 사용하는 후보 생성에서 앞쪽 상승 구간을 보존하면, 기존 후보와 계산 예산을 유지하면서 전체 데이터의 사용 가능한 참조 포함률을 개선할 수 있는가?

경쟁 설명: (H1) ±1 tap 표현이 지나치게 좁다. (H2) 양쪽 골짜기를 쓰는 돌출도가 뒤쪽 큰 봉우리와 합쳐진 앞쪽 상승을 제외한다. (H3) 후보 수를 늘려 기계적으로 참조를 포함할 뿐, 예산 초과·모호성 증가로 실용성이 없다. 2×2 비교와 전체 데이터 후보 부담으로 구분한다. 참조 포함은 선택 성공과 별개다.

## 권장 수정: 두 요인을 분리한 보수적 확장

기호: RX별 진폭 a[n]=|CIR[n]|, 두 RX 전체 최대 G, 국소 봉우리 시작 tap p, 기존 왼쪽 단조 골짜기 v, 기존 30% 선행 에지 e. 모든 진폭은 기존 선형 단위다. 참조·경로 ID·pose·정답·이전 프레임은 생성기에 제공하지 않는다.

### A. 선행 에지 한 점 주변에서 상승 구간으로 확장

기존 채택 봉우리에 대해 기존 후보를 보존하고, 정수 tap e부터 p까지 중 a[n] >= max(noise_floor, numeric_floor, 0.15*a[p])인 tap을 추가한다. 즉 기존 edge-1도 유지하고 뒤쪽은 봉우리까지 확장한다. 고정 ±2/±3로 누락 위치에 맞추지 않는다. 하강 구간은 추가하지 않는다. plateau는 기존 첫 tap p까지만 사용한다.

이는 특정 참조 위치를 추측하지 않고 동일한 관측 상승 구간에서 후보를 제공하는 규칙이다. 후보 개별 tap을 독립 물리 경로로 해석하지 않는다. 후보 간 상관과 같은 봉우리 소속을 유지한다.

### B. 앞쪽 상승 지지 조건을 추가 경로로 허용

기존 양측 prominence 채택 경로를 그대로 유지한다. 기존 BELOW_PROMINENCE 봉우리만 다음 추가 조건을 검사한다.

- 경계 봉우리 아님; 기존 절대 진폭·수치 지지 조건 만족.
- 왼쪽 국소 골짜기 a[v] < 0.30*a[p], 따라서 기존 방식의 e를 찾을 수 있음.
- 왼쪽 상승량 D_left = a[p]-a[v] >= max(noise_floor, 0.06*G).

조건을 만족하면 LEFT_RISE_SUPPORTED라는 별도 근거로 후보를 추가한다. 6%를 낮추지 않는다. 기존 양측 돌출도도 함께 기록해 뒤쪽 골짜기가 얕아 탈락했던 경우를 구분한다. B 단독은 기존 e±1 후보 규칙을 사용하고 A+B는 위 상승 구간 확장을 적용한다.

주의: 한쪽 상승 조건은 노이즈·사이드로브도 더 허용할 수 있다. 이것이 정당한 물리 경로 검출이라는 주장은 하지 않으며, 아래 전체 부담/합성 검증을 통과하기 전 채택하지 않는다. 완전 단조 어깨처럼 국소 최대가 없는 경우까지 해결하는 규칙은 아니다.

### 고정 사항

입력 잠금, Hann/FFT, 원래 receiver, signed s 계산, 30%/15%/6% 수치, 기존 noise/numeric floor, raw fallback, 두 모드, 최대 64 후보를 유지한다. 후보 합집합은 tap으로 중복 제거한다. cap을 넘으면 기존처럼 OVERFLOW/사용 불가로 기록한다. 몰래 잘라내거나 cap을 올리지 않는다.

기존 후보와 support 기록은 보존하고 추가 근거는 덧붙인다. 새 봉우리로 기존 group이 연결되는 경우 기존 group과 확장 group 매핑을 모두 기록한다. 그룹 병합과 유효 분모 변화가 없었던 것처럼 처리하지 않는다.

## 고정 비교표: 결과를 보고 조합을 추가하지 않음

|arm|후보 구간|봉우리 지지|
|---|---|---|
|V0|기존 e±1|기존 양측 돌출도|
|VA|기존 + e..p|기존 양측 돌출도|
|VB|기존 e±1|기존 또는 왼쪽 상승 지지|
|VAB (사전 지정 주안)|기존 + e..p|기존 또는 왼쪽 상승 지지|

VA/VB는 원인 분리용이다. VAB가 실패하면 같은 데이터에서 가장 좋은 arm으로 조용히 갈아타지 않는다. 결과를 보존하고 후속 개정으로 돌아간다. 임계값 grid search는 하지 않는다.

## 검증 순서와 전체 모집단

1. 구현 전 별도 개정 계약에 위 수식·arm·판정·입력 및 환경 해시를 고정한다. 원래 E1 결과는 보존한다.
2. V0가 기존 6,320 파형, 두 모드 12,640행, 기존 후보/로그/판정을 재현하는지 확인한다. 입력·키·분모 불일치 시 중단한다.
3. 같은 잠금 입력 전체에 네 arm을 적용한다. dynamic R2/R4/R5의 Full/Native-LoS, 정적 조건·좌표·yaw 등 INPUT_LOCK/SPLIT_MANIFEST에 포함된 전 항목을 유지한다. 누락 8건이나 큰 오차 87건만 실행하지 않는다. 참조는 평가기에만 제공한다.
4. 원본 정상, 1 tap 오차, 2 tap 이상 오차, 원본 무효, 참조 무효를 별도 집계한다. 참조 무효는 recall 분모에 넣지 않되 전체 입력/유효 출력/overflow 분모에서 삭제하지 않는다.
5. route별·파형별·기존 error episode별·정적 coordinate별로 paired 비교한다. episode 분리와 좌표/yaw 묶음은 기존 METRIC_SPEC 그대로 적용한다. IID packet 신뢰구간이나 독립 RF 환경 수를 주장하지 않는다.

## 지표와 사전 판정 제안

- 주요 성공 지표: 기존과 동일한 supported AND usable exact-tap 참조 포함률. Dynamic Full TWO_PORT_UNION의 큰 오차 전체 및 분모가 있는 각 route에서 각각 >=95%. ±1 허용으로 평가 기준을 바꾸지 않는다. 분모 0은 NOT_TESTED.
- 회귀 조건: 모든 기존 valid raw tap 보존, 기존 후보 집합 포함, 기존 usable 참조 성공의 신규 실패 0건. 후보가 늘어도 overflow로 usable 성공이 줄 수 있으므로 별도 검사한다.
- 예산 조건: 원래 usable이던 파형에서 신규 overflow 0건. 최대 64 유지. 후보 수 median/p95/max 및 64 대비 여유를 전체/정상/오류별로 보고한다.
- 실용성 진단: 후보 수 증가량, 추가 후보의 raw 대비 거리, group 수/병합, 지원 RX 수, 처리 시간·메모리, episode별 완전 회복과 최장 누락 구간. p95 후보 수와 실행 시간은 V0 대비 배수도 공개하되 사후로 합격선을 만들지 않는다. 이 항목만으로 배포 채택을 선언하지 않는다.
- 앞의 95%·회귀·예산 조건과 산술 검산이 모두 통과하면 '노출 개발 데이터에서 제한된 후보 가용성 개선'만 수용한다. 하나라도 실패하면 수정안 미수용. 입력 손상·검산 불일치는 판단 불가/실행 중단이다.
- 정상 프레임의 후보 증가를 false correction rate로 부르지 않는다. 참조 외 후보 전부를 가짜 물리 경로로 분류하지 않는다. E2 없이 선택 오류율·거리 개선·EKF 개선은 측정하지 않는다.

## 수학/구현 검증 및 추가 일반화 계획

자기 검산에서는 production helper를 재사용하지 않는 식 계산으로 v/e/D_left/후보 범위를 확인한다. 정수 후보·상태는 정확 일치, 정규화 진폭은 절대오차 1e-10을 기본 검사 허용값으로 고정한다. 경계값은 구현 규칙의 >=/<를 그대로 확인한다. zero/NaN/plateau/한 RX null/경계 봉우리/노이즈만 존재/넓은 단일 상승/이중 봉우리의 얕은 골짜기/64 초과를 포함한 결정적 합성 fixture를 작성한다. 합성 데이터는 RF 일반화 증거가 아니다.

이미 본 전체 corpus의 성공은 개발 재검증이다. 전체 데이터를 무작위 packet 분할하거나 현재 route를 제외해 다시 평가해도 진정한 holdout은 아니다. 일반화 검증은 규칙을 동결한 뒤, 아직 보지 않은 별도 scene/trajectory 묶음과 원본 데이터 출처를 먼저 등록해 같은 네 arm과 동일 gate로 1회 평가하는 별도 단계다. 단순 noise seed 복제는 새 RF 환경이 아니다. 현재 새 holdout의 존재·규모는 확인되지 않았으므로 일반화는 NOT_TESTED로 남긴다. 추가 데이터 생성·수집·noise stress 실행은 이 제안에 의해 자동 허용되지 않는다.

산출물: 개정 계약/해시, arm별 설정·실행 manifest, packet/lobe/candidate 로그, 전체 층화 비교표, 회귀·overflow 목록, 사례별 원인 변화, 검산 receipt 및 주장 경계. 자기 검산과 독립 감사는 별도다.
