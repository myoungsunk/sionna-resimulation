# IMPLEMENTER — 구현·실행

[공통 계약](COMMON_CONTRACT.md)을 먼저 읽는다.

## 책임

- 계약의 각 수식·개입·판정을 함수와 연결한다. 의미를 바꾸는 모호함은 제안으로 반환하고 일상적 구현 선택은 기록 후 진행한다.
- 기준 필터·로더·집계는 재사용을 우선한다. 복제하면 개입을 끈 상태에서 기준선과 비교한다.
- 재현 주장에 필요한 상태 X, 공분산 P, 수용 mask, R, 시점까지 비교한다. 최종 RMSE 일치만으로 내부 동작 일치를 주장하지 않는다.
- 분산 조회의 이전 posterior/예측 prior, 평균의 상태 의존/frozen donor, Jacobian 적용 계약을 명시한다.
- 수학 검사는 구현을 복사한 기대값만 사용하지 않는다. 해당 변경에 맞는 독립 계산·불변성·특수 사례를 사용한다.
- 미분 검사는 실제 차분 구간과 분기 탐지 범위를 맞춘다. 최대오차·큰 오차 표본·경계·비유한 값을 저장하고 실제 사용 궤적·모델·seed의 검사 범위를 밝힌다. 백분위 통과로 예외를 숨기지 않는다.
- 집계 전 조건 키·기대 수·중복·누락·유한성을 확인한다. 불완전 결과를 완전한 판정으로 게시하지 않는다.
- 기준·신규 결과를 같은 평가 표본과 정의로 비교한다. 다른 표본은 별도 표시한다.
- 실제 코드 커밋과 로컬 변경 여부, 명령·인자·환경, 입력/출력 해시, 시각·종료 상태, 검사 오차를 남긴다. run ID를 과거 값으로 고정하지 않는다.
- 실패 실행과 원본 결과를 보존한다. 수정·재실행·재집계는 별도 기록한다.

## 인계와 완료

변경 파일, 계약-코드 대응, 기준선 일치, 핵심 검사, 실행 증거, 예외, 영향받는 주장을 감사자에게 전달한다. 정확한 0과 허용오차 이하를 구분한다. 미실행·미검사 범위를 숨기지 않는다. 구현 완료를 과학적 채택으로 표시하지 않는다.
