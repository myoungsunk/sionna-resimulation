## 1. 이번에 완료한 범위와 핵심 결론

지정된 사전 감사 규칙에 따라 최소 구현 → 독립 수식 검산 → 합성 가설 대조 → 보관 데이터 진단 → 가설 불일치 분석 → 판단값 진단 수정 → 저장 결함 수정·재감사 → 최종 결과 확인을 실제 GitHub Actions에서 수행했다.

**가장 중요한 발견은 'DR 고장·RF 정상일 사후확률'과 'RF 거리 추정이 DR 거리 추정보다 정확할 사후확률'이 다른 사건이라는 점이다.** 이전 계획이 전자를 후자의 필수조건으로 두었던 것은 연구 목적보다 강한 요구였다.

이 수정은 기존 posterior를 읽는 진단의 수정이다. 실제 비선형 G2/G3 상태 갱신을 새로 채택하거나 재귀 융합을 수행한 결과는 아니다. 원래 G3 수치 적분 실패도 해소된 것으로 표시하지 않았다.

## 3. 최소 모델은 무엇인가

첫 미검증 단계는 '어느 센서를 우선할 확률을 어떻게 계산할 것인가'였다. 이를 분리하기 위해 반경 r에 대한 작은 혼합모델을 구현했다.

p(r,d,k | z) ∝ pi_d pi_k p(r|d) p(z|r,k), r>=2.2m.

DR normal/fault 2개 성분과 RF signed residual 4개 성분을 유지한다. fault prior=0.05, fault 추가 표준편차=2m, RF negative/positive/overcorrected/long-path 성분은 CONTRACT에 고정했다. 이들은 **합성 검증용 공학 가정이며 실제 gyro/CIR로 독립 보정된 모수가 아니다.**

Estimator 입력은 DR 거리 평균, DR 거리 표준편차, RF 거리뿐이다. 정답 위치/거리, 실제 주입된 Gyro Bias level, 올바른 센서 label을 입력하지 않았다. 이미 확인한 E1 반례가 시험 모형 설계에 영향을 줬으므로 같은 자료의 결과를 독립 검증으로 주장하지 않는다.

원본 dr_pred_range_sigma_m은 innovation 표준편차이므로 Rr=0.0068578637m²를 제곱값에서 한 번 빼 DR prior variance로 사용했다. 이를 빼지 않으면 RF noise를 prior에도 중복 반영하게 된다.

## 6. 원인 분석: 고장 판정과 거리 우위 판정은 다른 질문이다

고정된 두 거리 추정 d=DR, z=RF에 대해

(d-r)²-(z-r)² = (d-z)(d+z-2r).

따라서 d>z일 때, RF가 더 정확한 사건은 r<(d+z)/2이다. d<z라면 부등호가 반대이고 d=z면 strict win은 없다.

**직접 목표 확률**:
P(|z-r|<|d-r| | data) = F_posterior((d+z)/2), d>z.

이 확률을 계산하기 위해 특정 'DR fault AND RF inlier' 모드의 질량이 95%를 넘을 필요는 없다. RF가 완전한 inlier로 분류되지 않아도 DR보다 훨씬 가까운 값일 수 있기 때문이다.

동일 모델·모수·데이터를 유지한 두 확률 비교:

|조건|P(DR fault AND RF inlier)|P(RF 거리 오차 < DR 거리 오차)|직접 확률 95% 통과|
|---|---:|---:|---|
|C1|0.0039868|0.5266069|아니오|
|C2|0.9427463|0.9978216|예|
|C3|0.1603606|0.1714447|아니오|
|C4|0.6226249|0.6452514|아니오|

이 표는 고정된 미보정 모형 내부의 posterior 확률이다. 외부 자료에서 실제 정확도 95%를 보장하는 통계적 confidence라고 표현하지 않는다.

## 8. 진단 오류를 발견하고 수정한 실제 흐름

두 확률을 비교한 첫 run은 마지막 JSON export에서 numpy.int64를 직렬화하지 못해 실패했다. 사전 감사가 이 metadata 경로의 타입 오류를 놓쳤다.

- 영향: READOUT_RESULT.json 미저장, 해당 진단 최종 리시트 불완전.
- 보존: 이미 생성된 조건별 CSV, 이전 수식 검산, 원본 입력, 실패 run/artifact.
- 수정: group key의 NumPy scalar를 Python scalar로 바꾸고 allow_nan=False 적용.
- 재감사: 수정 소스 hash를 승인 영수증에 고정한 후 해당 진단만 재실행.
- 결과: 최종 JSON 저장·클라우드 실행 완료. 실패 전후 DIRECT_READOUT_BY_CONDITION.csv는 271바이트로 완전히 동일.
- 동일 SHA256: a1b0d09bc30dda9e6a65f4a6cb4ece80bcc59a59c10a5856c7ab3a7ff94fce81.

이 과정에서 모형 수식, prior 확률, RF likelihood, 수치 허용치, 0.95 판정값은 한 번도 바꾸지 않았다. 원래 실패 run을 소급 success로 바꾸지 않았다.

## 9. 어떤 진단은 계속했고, 어디서 멈췄는가

C2의 가설 미지지는 정확한 선형 수식이나 원본 자료 적격성을 무효로 하지 않는다. 따라서 미리 고정한 사전확률 민감도 9조합과 동일입력 대조는 계속했다.

사전확률 변화로 C2의 fault-event 확률은 약 0.726–0.989, C4는 약 0.035–0.969로 변했다. 같은 Range/DR 입력만으로는 사전 가정에 따라 고장 원인 판정이 크게 달라질 수 있다. 어느 모수가 성능이 좋았는지 보고 최종 모수로 고르지는 않았다.

서로 같은 입력인데 실제 정답이 다른 두 합성 세계는 이 제한된 입력만으로 원인을 보편적으로 확정할 수 없음을 보여준다. 그러나 '어떤 확률적 판단도 유용하지 않다'거나 '추가 gyro/CIR 정보로도 불가능하다'는 결론은 아니다.

이후 다른 모형으로 갈아타기 전에, 이미 존재하는 posterior의 판단값 자체가 질문과 일치하는지 한정 진단을 수행했다. 이는 새 물리 prior/학습 모형의 실행이 아니라 평가 대상 사건의 감리였다. 직접 거리 사건의 구현과 검산까지 마쳤고, 이를 실제 G2/G3 상태 갱신으로 채택하는 것은 다음 방향 확인 대상으로 남겼다.
