## 1. 요청 목적과 현재 결론

본 문서는 구현자에게 요청한 독립 감사 항목과 실제 완료된 감사 결과를 함께 기록한다. 대상은 동결된 V2 실행 계약에 따라 생성한 **사전 선정 8개 pose의 Native LoS/Full canary**이다. 완전한 917개 pose 주행 성능을 검증한 문서가 아니다.

독립 재계산에서 복소 채널 상대오차 RMS는 **`0.00010051515145524099`**였다. 동결 기준 **`0.0001`**을 약 **0.515151455%** 초과하므로, 구현자의 `HOLD_RF_PARITY` 판정을 그대로 확정한다. 최대 복소오차, 전력차 `s`, tap, 수신 포트 선택 등의 통과가 이 RMS 실패를 상쇄하지 않는다. [최종 원시 감사](audits/P0_CANARY_RAW_AUDIT_FINAL.json)와 [실행 QA](runs/P0_CANARY_V2/03_RF_CANARY_QA.json)의 판정이 일치한다.

현재 결론은 다음 두 항목으로 구분한다.

## 3. 요청했던 독립 검증과 완료 내역

최종 감사는 별도 Python 프로세스에서 [독립 원시 감사 스크립트](audits/audit_native_raw.py)를 실행했다. 획득 코드 `r1b_native.py`와 그 observer를 import하지 않았으며, Sionna·Mitsuba·DrJit Native 런타임을 import하거나 새 RF 계산을 호출하지 않았다. 모든 검사는 보존된 데이터와 동결 입력을 대상으로 수행했다.

### 3.1 입력·소스·실행 환경

V2 계약과 입력 매니페스트에 포함된 **201개 해시 대조, 101개 고유 파일 경로**를 검증했다. 완전한 FFD bank 두 개도 포함한다. 소스와 상속 계약 등 **97개 파일은 실제 실행 커밋의 바이트와 대조**했다. 원본 궤적의 pose ID 순서, 행 수, `t>=30 s` 행 수를 확인했다.

환경 기록의 고정 패키지 버전, Python 버전, Mitsuba variant, 스레드 수를 계약과 대조했다. 원래의 여섯 mesh·재료 바인딩뿐 아니라 canary 실행 디렉터리에 실제 생성된 여섯 PLY 파일의 해시를 검증했다. `ENVIRONMENT.json`의 Native object ID는 floor, ceiling, 양측 wall 및 양끝 end wall의 여섯 표면에 대응한다.

현재 실행 환경은 Python `3.12.14`이며, 과거 Native 실행 환경의 Python `3.11`과 다름이 계약에 공개되어 있다. 동일 호스트를 과거 실행과 비트 단위로 동일한 환경이라고 주장하지 않는다. 패키지 고정과 환경 공개는 물리 정합 기준을 면제하지 않는다.

### 3.2 경로 계수·지연에서 채널과 CIR 재구성

각 모드의 path offset, path count, 복소 계수, 지연, interaction, object ID를 검사했다. 모든 주파수에서 다음 식으로 채널을 재구성했다.

\[
H(f)=\sum_p a_p(f)\exp(-j2\pi f\tau_p).
\]

16개 모드별 채널은 저장된 `H`와 **비트 단위로 일치**했고, 동일한 동결 수학식으로 재구성한 16개 CIR도 저장값과 비트 단위로 일치했다. 합산 순서의 수치 영향을 별도로 확인하기 위해 보상 합산 결과도 기록했다.

독립 관측 계산은 FFT 호출에만 의존하지 않고, `sin²` 형태의 대칭 Hann window와 명시적인 역 DFT 행렬을 사용했다. 직접 DFT와 저장된 CIR 사이의 최대 절대 차이는 **`3.7787766985862485e-15`**였다. 이 비교의 부동소수점 반올림 검사는 저장 계산의 재구성 여부를 확인하는 용도이며, RF 물리 정합 허용오차를 바꾸는 근거가 아니다.

### 3.3 관측과 SourceFFD 비교

가장 큰 peak를 갖는 수신 포트를 선택한 뒤 그 포트의 peak 30% 이상에 처음 도달하는 공통 tap에서 두 포트 전력을 계산했다. LoS와 Full은 각각 자신의 관측 절차를 적용했다. 독립 재계산한 거리, `s`, power, tap 및 strongest port를 획득 로그와 대조했다.

Native 채널 비교에는 **`SourceFFD.physical_h_col()`**의 물리적 복소 위상을 유지했다. 기준 주파수 공통 위상이 제거된 중간 spectrum을 Native 비교 대상으로 바꾸지 않았고, gain이나 위상을 추정·정렬하지 않았다.

동일한 원본 pose와 검증된 bank에서 canonical SourceFFD, 별도 direct-field 계산, SourceFFD Jacobian을 다시 계산했다. x·y·psi에 대한 24개 유한차분 방향 모두 cell·tap·branch가 안정적이었으며 상속 기준을 통과했다. 감사의 중앙차분 간격은 획득 코드의 절반인 `5e-6`이었다. 비매끄러운 경계 이동을 유한차분 PASS로 간주하지 않는 원칙을 유지했다.

거리 모델의 `d+B_OLD`와 first-path detector의 이산 거리 결과는 구분했다. Native detector 거리를 SourceFFD detector 거리와 확인하며, 이를 연속 거리 모델의 일치 주장으로 바꾸지 않았다.

### 3.4 Full 직접경로와 별도 LoS

Full의 각 bin에서 interaction이 없고 기하 지연과 일치하는 직접경로가 정확히 하나인지 확인했다. **2,056개 주파수–pose 조합 모두 해당 조건을 충족**했다. 이 직접경로에서 재구성한 채널과 별도로 실행한 Native LoS 채널의 상대 차이는 전부 **0**이었다. Full에서 추출한 직접경로를 별도 LoS 실행 대신 사용한 것은 아니다.

## 4. 최종 수치와 수용 판정

pose별 Native–Source 복소 상대오차는 TX index 0의 두 RX와 전체 주파수를 포함해 다음처럼 정의한다.

\[
\rho_i=
\frac{\lVert H_i^{LoS}-H_i^{Source}\rVert_2}
     {\lVert H_i^{LoS}\rVert_2},
\qquad
\rho_{RMS}=\sqrt{\frac{1}{8}\sum_{i=1}^{8}\rho_i^2}.
\]

통계의 모집단은 사전에 선정한 8개 pose 전부다. pose를 제거하거나 반복 위치를 다른 가중치로 재정의하지 않았다.

| 검사 | 독립 재계산 결과 | 고정 상한·조건 | 판정 |
|---|---:|---:|---|
| 복소 상대오차 최대 | `0.00015950092587162026` | `0.0005` | PASS |
| **복소 상대오차 RMS** | **`0.00010051515145524099`** | **`0.0001`** | **HOLD** |
| `s` 절대오차 최대 | `5.364072265257036e-7` | `2e-5` | PASS |
| `s` RMSE | `2.0947930303123633e-7` | `2e-6` | PASS |
| Native–Source tap 불일치 | `0` | `0` | PASS |
| Native–Source branch 불일치 | `0` | `0` | PASS |
| Full 고유 직접경로 | `2056 / 2056` | 전 조합 | PASS |
| Full 직접경로–별도 LoS 상대오차 최대 | `0` | `0.0005` | PASS |
| Source–independent direct 상대오차 최대 | `1.884318087940217e-13` | `1e-10` | PASS |
| 안정적인 Jacobian 유한차분 | `24 / 24` | 기존 절대·상대오차 조건 | PASS |

최종 감사의 **1,219개 확인 항목 중 실제 실패 항목은 `EIGHT_POSE_COMPLEX_RMS` 하나**다. 모든 개별 pose의 최대오차 검사가 통과했어도, 전체 RMS 기준은 별도로 적용된다. 실행 QA의 모든 gate boolean과 최종 HOLD 상태는 독립 재계산과 일치한다.

비용 산술도 기록된 값과 대조했지만, 비용 검증은 실행 재개 승인이 아니다. 획득 시간 중앙값은 pose당 약 37.72초였고, 최초 pose를 포함한 최대값은 약 246.08초였다. 해당 통계로 계산한 917개 pose 추정치는 각각 약 9.61시간과 62.68시간이며, 최대 기록 RSS는 약 1,208.96 MiB다. 이는 기록값에서 계산한 추정치로서 완료 시간 보장이나 새로운 실행 비용 계약이 아니다.

## 5. 지연·위상 차이의 사후 진단과 해석 한계

[독립 지연 진단](audits/P0_DELAY_DIAGNOSTIC_INDEPENDENT.json)은 저장된 원시값만으로 오류를 분해했다. 새 Native 실행, 파라미터 fitting, phase/gain 정렬, 원시 데이터 변경은 **모두 0건**이다.

Native와 Source를 다음처럼 쓴다.

\[
H_N=A_Ne^{-j2\pi f\tau_N},\qquad
H_S=A_Se^{-j2\pi f\tau_G}.
\]

여기서 \(\tau_N\)은 보존된 Native 지연, \(\tau_G\)는 원래 입력 좌표에서 계산한 기하 지연이다. 오류는 다음 항등식으로 분해된다.

\[
H_N-H_S=
\underbrace{H_S\left(e^{-j2\pi f(\tau_N-\tau_G)}-1\right)}_{E_\tau}
+
\underbrace{(A_N-A_S)e^{-j2\pi f\tau_N}}_{E_A}.
\]

회전 전·중·후 pose `440, 458, 476`에서는 `tau_N-tau_G`가 모두 **`3.900169068688608e-15 s`**였으며, 이로부터 계산한 주파수별 위상 차이 RMS는 **`1.593250994072354e-4 rad`**였다. 알려진 지연 차이에서 계산한 항이 관측된 복소오차의 큰 부분을 설명한다.

8개 pose 전체에서 계수 잔차의 상대 norm 최대는 **`7.12948788473566e-7`**였고, 위 항등식 재구성의 수치 잔차는 **`9.55e-14` 미만**이었다. 계수 잔차에는 진폭과 계수 자체의 위상 차이가 모두 포함된다.

저장된 모든 LoS 지연값은 `float32`로 바꾸었다가 `float64`로 되돌려도 정확히 동일했다. 이는 수치 정밀도에 관한 원인 가설을 뒷받침하지만, 입력 좌표 변환·거리 계산·지연 계산·런타임 저장 중 어느 연산이 차이를 만들었는지를 단독으로 확정하지는 않는다.

**`E_A`의 작은 값이나 위상 진단 결과를 기존 수용 지표 대신 사용할 수 없다.** 진단 후에도 원래 복소 RMS `0.00010051515145524099`와 HOLD 판정은 그대로다. 이것은 다중경로의 주행 성능 영향이나 4상태 EKF 성능을 설명하는 완성된 결과가 아니다.

## 6. 계산 감사의 독립성 범위

이번 감사는 구현 역할과 구분된 AI 에이전트가 별도의 스크립트와 Python 프로세스로 수행했다. 원시 H 재구성 및 direct-DFT 관측 계산을 별도로 작성했으며, 획득 코드의 observer를 그대로 호출하는 방식으로 결론을 대체하지 않았다.

다만 다음 한계를 명시한다.

- 구현자와 감사자는 **같은 호스트·작업공간·데이터·동결된 라이브러리**를 사용했다. 별도 장비나 운영체제에서의 재현 검증이 아니다.
- canonical SourceFFD의 재평가에는 동결된 원래 SourceFFD 소스를 사용했다. 모든 수학·안테나 모델을 처음부터 독립 구현한 검증이라고 주장하지 않는다.
- 두 역할 사이에 요청, 코드 검토 의견 및 결과 메시지가 전달되었다. 완전히 차단된 맹검 심사가 아니다.
- 독립 인간 연구자, 외부 기관 또는 실측 장비가 수행한 심사가 아니다. **독립 인간 동료심사와 과학적 sign-off는 부여되지 않았다.**
- 데이터 해시와 계산 재현의 통과는 안테나 원천 데이터 자체의 물리적 정확성이나 실제 환경 일반화를 증명하지 않는다.

따라서 이 문서에서 “독립”은 **별도 역할·별도 프로세스·별도 계산으로 수행한 계산 감사**의 범위를 뜻한다.

## 8. 향후 정밀도 또는 실행 계약 개정 시 필수 요청사항

현재 동결 계약의 실패 중단 조건에 따라 더 많은 RF를 실행할 수 없다. 다음 내용은 재개 승인 자체가 아니라, **정밀도·수치 표현·비교 절차를 수정하려는 경우 제출해야 할 사전 검토 요청**이다.

1. **실패 실행을 그대로 보존한다.** V2 계약, 입력 매니페스트, 실행 커밋, 원 실행 로그, 환경, 8개 원시 NPZ와 pose JSON, 실행 QA, 모든 감사 receipt를 해시로 묶는다. 새 실행은 별도 ID·디렉터리·계약을 사용하며 현재 HOLD 기록을 교체하지 않는다.

2. **지연값의 수치 표현 경로를 코드와 자료로 식별한다.** 요청 좌표부터 Native 위치 표현, 거리 연산, 지연 산출, 저장 dtype, NumPy 변환, `exp(-j2pi f tau)` 계산까지의 자료형·단위·반올림 위치를 명시한다. 현재 확인된 것은 저장 지연의 float32 왕복 동일성과 지연 오류 분해다. 아직 확인하지 않은 런타임 내부 원인을 확정 사실로 적지 않는다.

3. **개정 이유와 효과를 RF 합격 결과에 맞추어 조정하지 않는다.** 정확한 기하식과 오차 전파를 사용해 수정의 필요성을 설명하고, 무엇이 변경되는지 결과를 보기 전에 고정한다. 실패한 회전 pose를 제거하거나, pose 가중치·기준 phase·분모·평균 방식 등을 합격에 유리하게 바꾸는 것은 허용된 정정으로 간주하지 않는다.

4. **새 동결 계약과 사전 승인을 확보한다.** dtype, 실행 variant, 채널 재구성, 기하 입력의 해석, Source–Native 비교 의미, solver 설정 중 변경되는 항목을 하나씩 명시한다. 모든 소스 SHA, 패키지, geometry, pose·bin 모집단, gate, 중단 조건, 원시 저장 명세, 비용 상한을 고정하고 별도 사전 계산 감사를 받는다. 현재 HOLD 이후 추가 Native RF는 그 계약에 대한 사전 승인 없이 실행하지 않는다.

5. **허용오차 완화를 가정하지 않는다.** 기본 검토 기준은 이번에 상속한 수치와 비교 정의다. 변경이 필요하다는 주장은 결과가 기준을 조금 넘었다는 이유로 정당화되지 않는다. 그러한 제안이 있다면 별도의 과학적 근거와 명시적인 사전 검토·승인이 필요하며, 승인 전에는 기존 실패를 PASS로 다시 표시할 수 없다.

6. **승인 범위는 새 canary부터 구분한다.** 수정이 승인되어도 곧바로 917개 전체 생성을 승인한 것으로 해석하지 않는다. 새 canary 원시 결과를 동일한 독립 재구성·관측·Source 정합·직접경로 검증으로 감사하고, 모든 gate 통과 및 비용 계약 확인 뒤에만 P1 진행 여부를 판단한다.

7. **논문용 후속 결과는 필요한 원시 모집단을 확보한 후 작성한다.** 완전한 917개 paired 자료, 입력·출력 해시와 모든 관측 로그가 확보되기 전에는 P2의 전체 관측오차나 P3의 Heading·XY RMSE를 제출하지 않는다. 4상태 필터 계약을 유지하고 기존 6상태 결과를 대용하지 않는다.

현재 원시 canary는 원인 분석과 재현 감사에 사용할 수 있다. 현재 자료만으로 원래 요청의 P0–P3 전체가 완료되었다고 선언하거나, 제IV장의 전체 경로 성능표를 확정할 수는 없다.
