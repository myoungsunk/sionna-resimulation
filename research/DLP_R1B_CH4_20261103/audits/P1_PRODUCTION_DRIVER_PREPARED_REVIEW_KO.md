# 생산용 RF 수집기 소스 검토 — 준비 완료, 미실행

## 판정

**`PREPARED_ONLY_UNEXECUTED`**. 이 기록은 생산 실행을 승인하지 않는다. 현재 P0 canary의 `HOLD_RF_PARITY`를 유지하며, 전체 917개 RF 생성·조립·EKF 실행을 승인하는 `PASS` 감사 자료로 사용할 수 없다.

검토자는 `/root/ekf_contract_review`이며 작성자와 다른 계산 에이전트이다. 동일 작업공간을 공유하므로 외부 인적 승인이나 별도 물리 환경 재현을 뜻하지 않는다.

## 확인한 실행 차단과 근거 구조

`load_locks`는 canary 상태가 `PASS`가 아니면 `PRODUCTION_BLOCKED_CANARY_NOT_PASS`로 중단한다. 이 검사는 생산 계획 읽기와 Native 초기화·계산 호출 전에 수행된다. 따라서 현재 HOLD에서는 생산 모드로 진행할 수 없다.

계획이 나중에 허용되는 경우에도 8개 canary의 순서·원시 파일 해시와 고정된 나머지 909개 pose를 확인한다. shard들의 합집합은 `0..916`에서 canary를 제외한 정확한 집합이어야 하며 중복과 누락을 허용하지 않는다. 조립 단계는 정확히 917개 pose를 다시 확인한다.

생산 명세 해시는 감사 참조와 명세 해시 자체를 제외한 내용으로 계산한다. 감사는 명세·코드·계약·canary 해시를 결합하며 최종 계획은 감사 파일의 해시를 포함한다. 이 구조에는 감사와 명세 사이의 순환 해시 의존성이 없다. 별도 감사자의 `PASS`와 `FROZEN` 생산 계획이 추가로 필요하다.

## 소스 수준에서 확인한 데이터 검증

shard 수집은 V2에 고정된 `r1b_native.initialize/acquire_pose`를 그대로 호출한다. 조립은 원시 복소 진폭·지연에서 주파수별 H를 다시 만들고 CIR, 공통 FP tap, 선택 포트와 관측값을 재계산한다. Native LoS 지연, Full 내 유일한 직접경로, 별도 LoS와의 정합 및 917개 전체의 RMS·최대오차·tap/port 조건을 검사한다. 연속 거리 모델의 기존 offset도 확인한다.

출력은 새 디렉터리를 사용한다. 원래 per-pose NPZ는 수집 위치에 남고 조립은 그 경로와 해시를 기록한다. 처리 가능한 계산 예외는 완료 기록과 가능한 Native 부분 배열을 남긴다. 전체 RMS 실패는 요약과 원시 파일 목록을 보존한 뒤 PASS manifest 작성을 중단한다.

## 남은 검증 경계

- 이 코드는 개별 shard 실행기이다. 여러 프로세스의 동시 실행·일괄 중단을 관리하는 감독기는 아니며, signal 종료나 `KeyboardInterrupt`의 복구·기록을 보장하는 검증은 수행하지 않았다. 미래의 병렬 계획에는 별도 감독과 전역 중단 동작이 필요하다.
- 조립은 해시로 보호한 수집 단계의 FD 기록과 SourceFFD 배열을 사용한다. SourceFFD와 finite difference 자체를 다시 실행하는 독립 모델 감사는 아니다.
- 전체 소스와 상속된 Native 호출을 읽었고 Python AST 파싱은 통과했다. 추가 수치 시험, 생산 RF, 조립, 필터 재귀는 실행하지 않았다.
- 생산 계획의 비용·자원·partition 승인과 실제 생산 후 감사는 남아 있다. 현재 HOLD에서 P2/P3 성능이나 논문 과학적 검증 완료를 주장할 수 없다.

허용오차를 사후 완화하거나 실패한 canary를 덮어쓰지 않고, 적용되는 별도 검토 절차를 통해 P0 문제를 해소한 뒤에만 다음 실행을 검토해야 한다.
