## 실패를 숨기지 않은 전달

요청 검증기 `verify_traces_multi.py`는 변경하지 않았다. 5세트 모두 `NOT_ALL_PASS`, exit code 1이다. 모든 실패는 `tag_xy`다. 파일명 tag는 소수점 네 자리로 반올림되지만 NPZ와 영수증은 더 정밀한 원 좌표를 저장한다. 요청 검증기는 파일명 숫자와 원 좌표를 1e-9로 직접 비교하여 대부분을 실패 처리한다. 예: R4_aA `x1.5087_y-0.1957`의 원 좌표와 영수증은 둘 다 `[1.508743, -0.195687]`이며, 요청의 `x{x:.4f}_y{y:.4f}` 규약으로 쓴 이름은 원 파일명과 일치한다.

별도 진단에서는 5,083/5,083개 모두 지정 네 자리 형식의 파일명과 일치하고 영수증·NPZ 좌표도 일치한다. 반올림 차이는 최대 약 0.00005 m다. 앵커 x, route task, nodes17, solver, materials 관련 실패와 versions/runner 경고는 0개다. 추가 shape·receipt 필수 키·node frequency 감사 이상도 0개다. 이 진단을 원 검증기 PASS로 대체하지 않는다. 검증기의 좌표 비교 correction 및 수용 여부는 요청자 판단 대상으로 남긴다.

## 무결성과 재현 자료

세트별 `SOURCE_FILE_MANIFEST.json`은 원격 파일명·bytes·SHA256 전 목록, `SHA256SUMS.txt`는 전달 후 검사 목록, `DELIVERY_MANIFEST.json`은 요청 파일 해시·원격 출처·검증 명령·exit code, `ADDITIONAL_AUDIT.json`은 원 좌표와 영수증 및 과거 생성 환경 진단이다. Tier 1/2 원 검증기 출력과 모든 실패 행은 `VERIFY_TIER1.log`, `VERIFY_TIER2.log`에 보존했다. 별도 요약은 `DELIVERY_STATUS.json`이다.

원격·로컬 원자료 파일의 SHA256/크기를 전수 비교하고, 커밋 전에 Git index의 실제 blob SHA256을 다시 전수 비교했다. NPZ에 대해 전용 세트 디렉터리에서만 LFS 및 텍스트 변환을 비활성화했고 원본 JSON 영수증도 바이트 보존했다. 루트 `.gitattributes`, 기존 요청서·결과, 다른 checkout의 미커밋 작업은 변경하지 않았다. 선택 PLY 메시·scene_shard는 요청상 불필요하여 제외했다.

G3 전 위치 경로 완전성 판정, G5 m0/m45 재생성 및 비교, LoS H 복구, 신규 Sionna 실행은 수행하지 않았다. **원자료 업로드 완료와 수용 기준 통과는 별도다.** `V01b FAIL`, `stage_B_allowed=false`는 유지한다.
