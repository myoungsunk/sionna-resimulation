# 논문 작성 시스템 운용 방식

논문은 **논리적 사실 정리 → Obsidian 초안 → 사용자 검토 → 수용·확정 → Word 작성** 순서로 작성한다. 현재 사용자의 지시가 이 문서보다 우선한다.

## 1. 문서 구성

원고는 작성 상태와 언어를 나누어 총 네 개의 노트로 운용한다. 논리 정리와 운용 안내는 별도의 보조 노트에 둔다.

| 문서 | 역할 |

| [[01b 본문 초안 - 물리 관측·모델·결과]] | 본문 III장 이후의 한글 작업본. 저장소 3부 초안을 옮긴 것이며 01의 장 번호로 아직 통합하지 않았다 |
| [[02 초안 - 영문]] | 영문 원고를 작성하고 수정하는 작업본 |

보조 노트는 다섯 번째 원고가 아니다. 한글과 영문은 의미·주장·인용 범위를 맞추되, 각 언어의 수정과 수용 상태를 따로 관리한다. 한글의 확정이 영문의 확정을 뜻하지 않는다.

## 2. 작성 순서

### ① 현재 내용과 수정 의도 확인

- 작성할 절, 기준 자료, 수정 범위를 먼저 확인한다.
- 사용자가 직접 수정한 문장·취소선·메모를 읽는다.
- 사용자가 의도 파악을 먼저 요청하면, 수정 이유를 추론해 설명하고 그 단계에서 멈춘다.
- 수정 진행 지시를 받으면 해당 범위의 편집을 수행한다.

### ② 논리적 사실 정리

- 문단을 쓰기 전에 필요한 사실을 짧은 번호 목록으로 쓴다.
- 한 항목에는 하나의 사실이나 논리 관계를 담는다.
- 문제 → 기존 대응 → 적용 조건·한계 → 본 연구의 과제 순서로 연결한다.
- 문헌에서 확인한 사실과 작성자의 해석을 구분한다.
- 사실 목록만 요청받았을 때에는 논문 문단까지 작성하지 않는다.

### ③ 초안 작성

- 정리한 사실의 순서를 따라 문단을 작성한다.
- 한 문단은 하나의 역할을 맡는다. 같은 설명은 합치고 반복을 줄인다.
- 필요한 기술적 조건은 남기되, 단순한 사실을 길게 설명하지 않는다.
- 장 번호·소제목·문단 구분은 검토 중 바꿀 수 있다.

### ④ 사용자 검토와 수정

검토 기준은 다음 세 가지다.

1. **논리:** 앞 문장이 다음 문장의 근거가 되는가? 결론이 근거보다 강하지 않은가?
2. **순서:** 필요한 개념을 먼저 소개하고, 문제에서 대응과 한계로 자연스럽게 이어지는가?
3. **전문성·가독성·연구 특징:** 용어와 조건이 정확한가? 쉽게 읽히는가? 실제 연구 모델과 맞는가?

수정은 요청한 범위에 한정한다. 다른 절과 확정본은 보존한다. 통합·삭제·재배치가 요청된 범위에서는 중복 문장과 편집 메모를 정리할 수 있다.

### ⑤ 수용·확정

문서 간 반영 순서는 다음과 같다. 2026-11-02 사용자 지시로 정했다.

1. **한글 초안이 최신 수정본이다.** 모든 수정은 한글 초안에서 먼저 반영한다.
2. **영문 초안은 수정된 한글 초안을 기준으로 갱신한다.** 논문 포맷과 형식을 함께 적용한다. 한글과 독립적으로 영문을 먼저 고치지 않는다.
3. **수용·확정 노트는 한글 초안과 영문 초안 양쪽에서 승인받은 뒤에 반영한다.** 한쪽 언어의 승인만으로 확정본을 갱신하지 않는다.

- 사용자가 수용한 범위만 해당 언어의 수용·확정 노트에 옮긴다.
- 일부 문단을 제외했다면 그 제외 범위를 기록한다.
- 초안의 후속 수정을 확정본에 자동 반영하지 않는다.
- 확정본의 변경은 사용자가 지시한 범위에서 수행한다.

### ⑥ Word 작성

- 사용자가 Obsidian 초안을 확인한 뒤 Word 작성 단계로 진행한다.
- Word 형식은 기본적으로 IEEE 형식을 따른다. 투고처가 정해지면 해당 공식 템플릿과 규정을 적용한다.
- 변환할 언어와 수용 범위를 기준으로 작성한다. 미확정 문단을 자동 포함하지 않는다.
- Word 생성과 표시 검증을 마친 뒤 결과를 전달한다.

## 3. 문체와 인용

- 최대한 단순하고 짧게 쓴다. 사실을 먼저 말하고 필요한 설명을 붙인다.
- 본문에서 선행연구 저자 이름을 서술의 주어로 쓰지 않는다.
- **“[12]의 방법은 채널 특징으로 거리오차를 보정한다.”**와 같이 쓴다.
- “저자명 등은 … 하였다 [12].” 형식은 사용하지 않는다.
- 참고문헌의 정식 서지에는 저자명을 기재한다.
- 여러 사례는 각 방법이 무엇을 이용하고 무엇을 바꾸는지 설명한다. 논문 목록만 나열하지 않는다.
- 기존 번호는 가능한 한 유지하고, 새 문헌은 중복 없이 추가한다. 최종 정리 시 IEEE 인용 순서와 번호를 점검한다.
- 같은 문헌의 초록·공개본·최종 출판본 중 무엇을 확인했는지 보조 기록에 남긴다.

## 4. 근거와 주장

캔바스는 구성의 출발점이며, 그 안의 모든 주장을 확정된 사실로 취급하지 않는다. 실제 논문 내용과 원문 근거를 우선한다.

- 논리 비약이나 잘못된 주장이 발견되면 **문제 문장 → 잘못된 이유 → 논문에 미치는 영향 → 수정·보강 방향**을 구체적으로 설명한다.
- 관측량·하드웨어·환경·운동 가정이 다른 방법을 같은 조건처럼 비교하지 않는다.
- 다중경로와 NLOS, 거리오차와 수신 신호 왜곡을 구분한다.
- 시간에 따른 상태 갱신과 관측오차의 시간상관 모델링을 구분한다.
- 보정된 관측의 오차 감소와 최종 위치·Heading 오차 감소를 구분한다.
- 평가하지 않은 환경·모델·성능으로 결론을 확대하지 않는다.
- 본 모델의 설명은 현재 대표 모델과 일치시킨다. 거리 평균 보정, 편파 추가분산, 4상태 EKF의 역할을 혼동하지 않는다.
- 미확인 내용은 보강 사항으로 남긴다. 근거를 만들어 채우지 않는다.

상세 근거와 검토 메모는 보조 노트나 원고의 검토 부록에 둔다. 논문 본문에는 독자가 논리를 이해하는 데 필요한 내용만 남긴다. 문장 수정만을 위해 새로운 실험이나 별도의 연구 절차를 만들지 않는다.

## 5. 수식·특수문자와 형식 확인

### Obsidian

- UTF-8 Markdown으로 저장한다.
- 수식은 MathJax 문법을 사용한다. 인라인 수식은 `$...$`, 독립 수식은 `$$...$$`로 작성한다.
- 수식·기호가 들어간 부분은 문법과 실제 표시를 확인한다.
- 취소선·편집 메모가 논문 본문에 실수로 남지 않도록 확인한다.

### Word

- 수식은 Word에서 표시·편집 가능한 수식으로 옮기고, 원시 LaTeX 문자열이 그대로 남지 않도록 한다.
- 그리스 문자, 아래·위 첨자, 각도 기호, 수학 기호, 한글·영문 글꼴을 확인한다.
- IEEE 형식에 맞춰 제목·단·인용·참고문헌·그림·표·수식 번호를 점검한다.
- 생성한 파일을 렌더링해 줄바꿈·넘침·기호 누락·수식 잘림을 확인한다.

문법 검사 통과와 실제 표시 확인은 구분해서 보고한다. 검사하지 않은 화면이나 Word 파일을 검증 완료라고 표시하지 않는다.

## 6. 현재 상태

2026-11-02 기준이며, 후속 사용자 지시에 따라 갱신한다.

- 한글 Introduction은 마지막 결과 문단을 제외한 7개 문단이 수용·확정되어 있다. 첫 문단의 `[ref]`·`[R1]` 자리표시자는 보완이 남아 있다.
- 한글 Related Work A·B절은 2026-11-02 검토 결과를 반영해 수정했다. 변경 구간은 하이라이트, 수정 전 문장은 접힌 취소선 노트에 보존했으며 대응 기록은 초안의 검토 부록 D에 있다. 구성과 문장은 아직 확정되지 않았다.
- 본문 인용은 "[N]의 방법은" 형식으로 통일했다. 한글 초안과 한글 수용·확정본 모두 적용했다.
- 한글 수용·확정본은 **한글 단독 기준본**이다. 표기 통일까지 반영되어 있으나 승인은 한글뿐이므로, 영문 갱신과 승인 전에는 Word 작성 기준으로 쓰지 않는다. 본문에는 추적 표시를 두지 않고 그 기록은 초안에 보존한다.
- 관측량 용어는 한글 원고에서 "정규화 전력차"로 통일했다. 저장소 문서는 "signed 편파비"를 쓰므로 어느 표기를 쓸지 결정이 남아 있다.
- A절의 논리적 사실은 [[00 논리적 사실 - Related Work A]]에서, 저장소의 수치·모델 정의·적용 경계는 [[00 GitHub 근거 - 수치와 적용 경계]]에서 관리한다.
- 영문 초안은 한글 확정본과 논리가 다른 이전 세대 원고다. 분석 목표형으로 서술되어 있고 Related Work가 없으며 참고문헌이 [1]–[9]뿐이다. 위 ⑤의 순서에 따라 한글 기준으로 갱신해야 한다.
- 본문 III장 이후(시뮬레이션 설정, Dual-LP 관측, 관측 특성 분석, 모델, 성능, 한계)는 초안이 없다. 저장소의 고정 구성과 수치는 보조 노트에 정리되어 있다.
- 인용 번호의 IEEE 순차 재배열과 Word 작성은 구성 확정 이후 단계다.

## 7. 작업 완료 보고

작업 후에는 변경한 문서·범위, 실제 수행한 확인, 남은 보완 사항을 짧게 보고한다. 초안 작성, 사용자 수용, Word 생성, 표시 검증을 서로 다른 상태로 구분한다.
